# QuarryAI Brand and SEO Guidance

This file documents how QuarryAI should be described and presented consistently across the repository, website, and public-facing documentation.

## Official product name

Use the official product name as: QuarryAI.

The official website is:

https://quarryai.dpdns.org/

## One-sentence product description

QuarryAI is an AI-powered Minecraft Paper plugin generator that helps server owners and developers turn natural-language ideas into Paper plugin workflows and compiled plugin outputs.

## Recommended public project description

QuarryAI is an AI-powered Minecraft Paper plugin generator that helps server owners create custom plugins from natural-language descriptions.

## Terminology guidance

Use these terms naturally when describing the project:

- QuarryAI
- AI Minecraft plugin generator
- Minecraft Paper plugin generator
- Paper plugin development
- Minecraft plugin installation
- Minecraft plugin ideas
- AI-assisted plugin creation

Keep the language precise and readable. Avoid forcing repeated keywords into headings or paragraph copy.

## Consistency rules

To keep the project consistent:

- use the same product name in the README, website metadata, and docs
- link to the official website consistently
- describe the project as a Paper plugin generator and public website when that matches the repository evidence
- keep example pages, guides, and pricing references aligned to the live site
- avoid claims about private infrastructure or unsupported project features

## Rules against spammy SEO behavior

Do not:

- stuff the same keyword into every heading
- create fake reviews or fabricated testimonials
- use duplicate text across pages as a ranking tactic
- make unsupported claims about features, output quality, or user numbers
- invent non-existent pages or URLs
- describe the repo as more than it is if the code does not support that claim

## Link management

If the official domain changes, update the following in a consistent pass:

- README links
- website metadata and canonical tags
- any documentation references
- social previews and public marketing copy
- GitHub About description and website fields

## Internal recommendation

The repository should be written to help real developers and server owners understand the product, not to manipulate search engines. Clear technical descriptions, honest accuracy, and useful documentation are more valuable than SEO padding.
